See it in 30 seconds

Three commands. Same local runtime.

Start with tests, try anonymous Apex, then narrow the loop to files changed since main.

test 
$ glade test --project .
-> local Apex tests
exec 
$ glade exec 'System.debug(1+1);'
-> USER_DEBUG 2
changed 
$ glade test --changed-since origin/main
-> affected tests only

Runtime surface

The Apex pieces, cut to run locally.

The parser, checker, VM, data runtime, tools, and compatibility fixtures all ship in the same binary.

Run Apex tests

Affected-test selection

SOQL

DML + triggers

Insert, update, delete, validate, roll back, and fire supported triggers.

Governor limits

Track runtime limits so local execution fails where supported behavior should fail.

LSP + DAP

Local HTTP API server

Compatibility dashboard

The same runtime everywhere.

01

Parse and index. Apex files, triggers, schema metadata, and project layout become a local symbol graph.

02

Check and lower. Diagnostics are shaped for machines, then supported code lowers into executable IR.

03

Execute locally. The VM routes SObjects, SOQL, DML, triggers, limits, storage, and common platform APIs.
