# Native capture: direct synthetic portal roles

Three fresh 30-day Developer scratch orgs were created from campaign Dev Hubs. At API 62 and 67 synthetic tests attempted direct role creation: portal account without portal type; with Partner type on ordinary accounts; and with Partner type on partner-enabled accounts. The latter used Communities, a synthetic owner role and an email-suppressed scratch user update within the rolled-back test. The populated role attempts were rejected respectively for missing portal type, accounts not enabled for the portal type, and system-maintained portal fields. The ordinary null role control succeeded. These are setup boundaries, not ordering results. No email was sent. All three scratch orgs were deleted, and their ScratchOrgInfo statuses verified as Deleted.
