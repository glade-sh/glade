Salesforce Developer Edition scratch orgs on the campaign Dev Hubs; capture date 2026-11-22. One 1-day scratch org per capture, deleted and verified gone. Synthetic project and metadata only.

Four captures, each at API 62.0 and 67.0 (66.0 added for the event handler shapes). Every row of every org.tsv is an answer; rows whose residue column starts with tainted: are kept but never asserted.

- share_mdt_basic_queries: the administrator reads a custom object's share table (static and dynamic SOQL, manual and RowCause shares) and custom metadata MasterLabel, Label and DeveloperName in select, WHERE, ORDER BY, getInstance and constructor forms. Native ignores ORDER BY MasterLabel and ORDER BY Label on a custom metadata type, in both directions, and keeps the default record order; ORDER BY DeveloperName orders normally.
- share_mdt_runas_access: users on the Minimum Access, Standard User and System Administrator profiles with permission sets that grant or withhold object access and the Custom Metadata Types grant. A custom metadata type is readable in USER_MODE, with MasterLabel, DeveloperName and custom fields and no field permission, exactly when the user holds the Custom Metadata Types grant (or is the administrator); otherwise "sObject type is not supported", and the describe reports false for the type and each field. The share table is accessible and creatable in the describe exactly when its parent object is accessible, and its columns need no field permission. At API 67.0 the ungranted user's default queries are denied as well. Share rows are visible exactly when the user can see the parent record.
- share_table_visibility: the same users with a manual share to two of them and a record each user creates. Share rows follow the visibility of the parent record, in user and system mode, static and dynamic; the owner row of a user's own record shows.
- share_mdt_event_runas: BatchApexErrorEvent from named tests. Below API 67.0 a test publishes the event with any of its eight fields set, singly or together, through EventBus.publish and Database.insertImmediate, and the after-insert trigger runs at Test.stopTest(); an exception thrown by that trigger does not reach the test. At API 67.0 the publication returns a failed SaveResult (CANNOT_INSERT_UPDATE_ACTIVATE_ENTITY) and no trigger runs. The describe reports the event not createable. Assigning Message after construction raises "Field is not writeable" at API 67.0 and in anonymous execution; the constructor argument is always accepted. The anonymous rows publish and are tainted by the capture tool; they are listed, not asserted.
- share_mdt_profile_grant: a user on a custom profile whose XML enables the Custom Metadata Types grant reads the type (describe true, USER_MODE query returns the records); a user on a custom profile without the grant gets describe false and "sObject type is not supported". Same at 62.0 and 67.0.

Observed and not modeled, so no assertion covers them:
- A Public Read/Write custom object has no share table: Database.query on its __Share raises "sObject type is not supported" and the global describe lacks it. Glade still generates the table.
- Schema.X__Share.RowCause.Reason__c compiles and runs natively; Glade rejects it at compile time.
- A metadata relationship field to EntityDefinition read in USER_MODE by a Minimum Access user holding the Custom Metadata Types grant returns null parents, filters to no rows and raises no error; Glade raises "No such column ... for USER_MODE".
- new Account(ParentId = 'bad_rec_id_0001') raises StringException natively; Glade accepts it.
