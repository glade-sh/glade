# Native capture: service-report layout lookup null ordering

A fresh 30-day Developer scratch org was created from a campaign Dev Hub. At Apex API 62 and 67, a named @IsTest(SeeAllData=true) test queried the scratch org's single default ServiceReportLayout and inserted only synthetic WorkOrder, WorkOrderLineItem and WorkType records in the rollback-only test transaction. For each lookup it re-queried one null and one populated reference under ascending/descending NULLS FIRST/LAST. This two-row matrix distinguishes NULLS placement; it does not establish ordering among distinct populated parents. An invalid WorkOrderLineItem is the rejection control. Captured observations contain no record IDs or usernames. The scratch org was deleted and ScratchOrgInfo status verified as Deleted.
