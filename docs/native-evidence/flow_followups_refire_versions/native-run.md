# Native capture: Flow refire rejection source versions and batch sizes

A fresh 30-day scratch org was created from a campaign Dev Hub and the synthetic project deployed. Flow, action, trigger and guard source versions were deployed together at 67, 66, 65, 64, 63 and 62; exact metadata for each is saved under source-<version>. The API 62 named test ran for each source version, and the API 67 named test additionally ran with API 67 sources. The before-update trigger rejects the first or second record of a two-record batch, the first or last of a three-record batch, or the middle of a 200-record batch. Error index, count, status, null ID/field metadata and stable message predicates are recorded; full normalized messages are retained for two-record cases. Synthetic IDs are replaced before export and the public developer-guide link retained. Successful 2/3/200 refire and overlength controls are included. An earlier scratch attempt emitted no API 67 row because the assertion payload was too large; both scratch orgs were deleted and verified Deleted.
