# Native capture: Flow action fault list boundaries

A fresh 30-day scratch org was created from a campaign Dev Hub. Only the synthetic metadata in `project/` was deployed. The synthetic permission set was assigned in the test; test insert statements explicitly use system mode. The project contains Flow and action API 62 sources; the ceiling files are the exact API 67 variants. API 67 Flow/action was deployed first and tests at 62 and 67 were run, then Flow/action were redeployed at API 62 and the API 62 test rerun. Each boundary summary verifies every index, status, and message predicate before recording its boolean. Observations are JSON assertion payloads with identifiers, email addresses, and URLs scrubbed. The clean input is the acceptance control. The scratch org was deleted and its ScratchOrgInfo status verified as Deleted.
