# Native capture: Flow refire trigger batch boundaries

A fresh 30-day scratch org was created from a campaign Dev Hub and the synthetic project deployed. Project Flow, action, trigger and guard sources are API 62; ceiling files are their API 67 variants. API 67 Flow/action/trigger/guard was deployed first and test classes at 62 and 67 run, then all four were redeployed at API 62 and the 62 class rerun. Two, three and 200 records enter an after-save Flow whose writes refire an after-update trigger. The trigger records batch sizes and old/new values and makes one guarded nested update of the second record. An overlength input provides a rejection control. Observations are JSON assertion payloads with identifiers, email addresses and URLs scrubbed. The scratch org was deleted and ScratchOrgInfo status verified as Deleted.
