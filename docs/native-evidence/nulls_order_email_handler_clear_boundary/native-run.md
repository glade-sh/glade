# Native capture: inactive email handler null clear

A fresh 30-day Developer scratch org was created from a campaign Dev Hub. Two synthetic handler classes and three inactive EmailServicesFunction records were created at each API version; no email addresses were configured. A Salesforce data REST PATCH with JSON body {"ApexClassId":null} rejected the clear with FIELD_INTEGRITY_EXCEPTION at API 62 and 67, and re-query showed all three references still populated, with two distinct values. A separate null-create control was rejected. No email was sent. This is a setup boundary, not an ordering result. The synthetic functions were deleted and the scratch org was deleted, with ScratchOrgInfo status verified as Deleted. Earlier attempts that submitted the literal string null or failed transport did not establish null behavior; their scratch orgs were also deleted and verified.
