# Native capture: Flow refire with a start-filter subset

A fresh 30-day scratch org was created from a campaign Dev Hub and the synthetic project deployed. Project Flow, action, trigger and guard sources are API 62; ceiling files are their API 67 variants. API 67 Flow/action/trigger/guard was deployed first and test classes at 62 and 67 run, then all four were redeployed at API 62 and the 62 class rerun. Two, three and 199 matching records are inserted with one nonmatching record. The matching records enter an after-save Flow whose writes refire before- and after-update triggers; a guarded nested update of the second record records old/new values. The last case reaches the 200-input boundary. An overlength input provides a rejection control. Observations are JSON assertion payloads with identifiers, email addresses and URLs scrubbed. The scratch org was deleted and ScratchOrgInfo status verified as Deleted.
