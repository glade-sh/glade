# Native capture: Flow batch admission with filtered record update

A fresh 30-day scratch org was created from a campaign Dev Hub and the synthetic project deployed. The project contains Flow and action API 62 sources; the ceiling files are the exact API 67 variants. API 67 Flow/action was deployed first and test classes at 62 and 67 run, then both were redeployed at API 62 and the 62 class rerun. The action runs before a filtered update to a separate synthetic target. Tests cover two matching source records, two matching plus one nonmatching start-filter control, 200 matching records, and an overlength rejection. The recorded action size lists are copied before subsequent cases. The initial scratch attempt retained shared mutable list references and did not establish earlier invocation sizes; both scratch orgs were deleted and ScratchOrgInfo status verified as Deleted. Observations are JSON assertion payloads with identifiers, email addresses and URLs scrubbed.
